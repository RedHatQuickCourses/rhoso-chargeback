#  Verifying successful Chargeback activation

= Verifying Successful Chargeback Activation
:page-aliases: chargeback-activation-verification.adoc

After successfully enabling the Chargeback feature in Red Hat OpenStack Platform (RHOSP) as part of RHOSO, it is crucial to verify that all components are active and functioning correctly. This verification step ensures that the system is ready to collect resource consumption data, process it according to rating definitions, and generate accurate chargeback reports. Without proper verification, you risk incomplete data collection or incorrect billing.

== Understanding Chargeback Activation Verification

Successful Chargeback activation means that the necessary backend services are running, integrated, and prepared to collect and process consumption metrics. In an RHOSP environment, RHOSO Chargeback leverages several core OpenStack services for metering and data storage, primarily:

*   **Ceilometer**: The metering service responsible for collecting various resource usage metrics (CPU, RAM, disk I/O, network I/O) from OpenStack components.
*   **Gnocchi**: A time-series database optimized for storing the vast amounts of metric data collected by Ceilometer.
*   **Aodh**: The alarming service, which, while not directly responsible for data collection, is part of the telemetry ecosystem and its health indicates overall system stability.

Additionally, any specific RHOSO Chargeback components (if they manifest as distinct services or modules within RHOSP) must also be operational. Verification typically involves:

*   Checking the operational status of these critical OpenStack services.
*   Confirming the visibility and accessibility of Chargeback-related features within the RHOSP Horizon dashboard.
*   Optionally, performing a preliminary check for active data collection to ensure the foundation for chargeback is solid.

== Hands-on Lab: Verifying Chargeback Activation

This lab guides you through the essential steps to confirm that RHOSO Chargeback has been successfully activated in your RHOSP environment.

=== Prerequisites

*   You have administrative access to your RHOSP environment (e.g., SSH access to controller nodes).
*   You have enabled Chargeback in RHOSP as per the previous section xref:enabling-chargeback.adoc[Enabling Chargeback in RHOSP].
*   You have credentials for an administrative user in the RHOSP Horizon dashboard.

=== Procedure: Verify Service Status

The first critical step is to ensure that the core OpenStack services required for RHOSO Chargeback are running and healthy.

.  **Log in to an RHOSP Controller Node:**
   Open a terminal and establish an SSH connection to one of your RHOSP controller nodes. This is typically done using the `heat-admin` user.

   ```bash
   ssh heat-admin@<controller-node-ip>
   ```
   Replace `<controller-node-ip>` with the actual IP address of one of your controller nodes.

.  **Source the `overcloudrc` file (if necessary):**
   If you intend to use OpenStack client commands, ensure your environment is configured by sourcing the `overcloudrc` file.

   ```bash
   source ~/overcloudrc
   ```

.  **Check OpenStack Service Status using `openstack service list`:**
   Use the `openstack service list` command to verify the status of key services that Chargeback depends on. Look for the core telemetry services.

   ```bash
   openstack service list | grep -E 'ceilometer|gnocchi|aodh'
   ```

   *Expected Output (example):*
   ```text
   | <ID> | ceilometer             | metering             | True  |
   | <ID> | gnocchi                | metric               | True  |
   | <ID> | aodh                   | alarming             | True  |
   ```
   Confirm that `ceilometer`, `gnocchi`, and `aodh` services are listed, and their `Enabled` column shows `True`.

.  **Verify Container Statuses (for containerized deployments):**
   In modern RHOSP deployments, services run within containers. Use `podman` (or `docker` in older versions) to check their health directly on the controller node.

   ```bash
   sudo podman ps -a | grep -E 'ceilometer|gnocchi|aodh|chargeback'
   ```
   *Expected Output (example - focus on `Up` status):*
   ```text
   <CONTAINER_ID>  <IMAGE>  <COMMAND>  <CREATED>  <STATUS>      <PORTS>  <NAMES>
   ...             ...      ...        ...        Up ...        ...      ceilometer_api
   ...             ...      ...        ...        Up ...        ...      gnocchi_api
   ...             ...      ...        ...        Up ...        ...      aodh_listener
   ...             ...      ...        ...        Up ...        ...      rhoso_chargeback_processor (if specific RHOSO service exists)
   ```
   Verify that containers related to `ceilometer`, `gnocchi`, `aodh`, and any specific `rhoso_chargeback` containers (if applicable to your RHOSO deployment) are in an `Up` state.

=== Procedure: Verify RHOSP Dashboard Integration

After confirming the backend service status, ensure that the RHOSO Chargeback features are accessible and visible within the RHOSP web interface (Horizon).

.  **Log in to the RHOSP Horizon Dashboard:**
   Open your web browser and navigate to the RHOSP dashboard URL (e.g., `https://<horizon-ip>/dashboard`). Log in with an administrative user account.

.  **Navigate to the Chargeback Section:**
   Within the Horizon dashboard, locate the navigation menu. Chargeback-related features are typically found under the `Admin` tab or a dedicated top-level menu item.

   *   Look for a section titled `Chargeback`, `Billing`, `Metering & Billing`, or similar. This might be a direct tab or a sub-menu item under `Admin` -> `System` or `Project` -> `Metering`.

.  **Confirm Chargeback Menu Items:**
   Verify that new menu items or dashboards related to "Rating Definitions", "Rating Rules", "Reports", or "Invoices" are present and accessible. Clicking on these items should load the respective pages without displaying errors, indicating that the UI components are correctly integrated.

=== Procedure: Verify Basic Data Collection (Optional but Recommended)

While detailed data collection verification is typically covered when "Using the Chargeback Feature," a quick check here can provide early confidence that metering data is actively being sent and stored.

.  **Access Metering/Telemetry Data in Horizon:**
   Within the RHOSP Horizon dashboard, navigate to the `Project` tab, then select `Metering` (or `Telemetry`).

.  **Review Resource Metrics:**
   On the Metering page, you should see a list of resources and their associated metrics. Select a running instance or volume and review its metrics (e.g., CPU utilization, RAM usage, disk read/write bytes). The presence of recent and changing data points indicates that Ceilometer is collecting metrics and Gnocchi is storing them effectively, which is foundational for Chargeback calculations.

=== Summary of Verification

By successfully completing these verification steps, you have confirmed that:

*   The underlying OpenStack services required by RHOSO Chargeback (Ceilometer, Gnocchi, Aodh) are operational.
*   Any specific RHOSO Chargeback components are running (if applicable).
*   The Chargeback features are correctly integrated and accessible within the RHOSP Horizon dashboard.
*   Basic metering data is actively being collected, establishing the necessary data stream for chargeback calculations.

You are now ready to proceed with configuring rating definitions and rules as part of xref:using-chargeback.adoc[Using the Chargeback Feature].

== Basic Chargeback Activation Troubleshooting

If you encounter issues during the verification process:

*   **Service Not Running:**
    *   Re-check deployment logs for specific errors during service startup (`journalctl -u <service-name>` on controller nodes, or `sudo podman logs <container-name>`).
    *   Ensure all prerequisites for Chargeback deployment were met.
*   **UI Not Visible or Errors:**
    *   Clear your web browser's cache and cookies, or try an incognito window/different browser.
    *   Verify that your administrative user account has the necessary roles and permissions to view Chargeback features. Role-Based Access Control (RBAC) misconfigurations are a common cause.
    *   Check Horizon logs (`/var/log/horizon/horizon.log` on the Horizon server) for UI-specific errors.
*   **No Metering Data:**
    *   Verify that Ceilometer agents are running on compute nodes (if applicable to your RHOSP version).
    *   Check connectivity between Ceilometer components, the message bus (RabbitMQ), and Gnocchi.
    *   Review Gnocchi logs for errors related to metric storage.
